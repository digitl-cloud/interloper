Schemas & normalization¶

A schema is an asset's data contract; a normalizer coerces the vendor's rows into it and a materialization strategy decides how they land.

schema ¶

schema(cls: type) -> type[Schema]

schema(
    *, key: str = ..., name: str = ...
) -> Callable[[type], type[Schema]]

schema(
    cls: type | None = None,
    /,
    *,
    key: str | None = None,
    name: str | None = None,
) -> type[Schema] | Callable[[type], type[Schema]]

Create a Schema subclass from a decorated class.

Can be used bare or with arguments:

@schema
class UserSchema:
    id: int
    name: str
    email: str

@schema(key="custom", name="Custom Schema")
class OtherSchema:
    value: float

The decorated class's annotations and attributes become the Schema subclass body.

Schema ¶

Schema(**data: Any)

Bases: Serializable

Defines the expected output structure of an asset.

Subclass to declare output fields:

class UserSchema(Schema):
    id: int
    name: str
    email: str

Class methods provide schema operations on list[dict] data:

Schema.infer(rows)
UserSchema.validate_rows(rows)
UserSchema.reconcile(rows)

field_specs ¶

field_specs() -> list[FieldSpec]

Extract backend-agnostic field specs from this schema.

Fields declared by Schema itself (framework plumbing, if any) are excluded — only the subclass's data columns count. Fields come out in declaration order: Serializable normalizes model_fields so a column shadowing a parent ClassVar (name, key) is not hoisted out of place.

Returns:

Type Description
list[FieldSpec]

One FieldSpec per declared data field, in declaration order.

json_schema ¶

json_schema() -> dict[str, Any]

JSON Schema for this schema's data fields only.

Like pydantic.BaseModel.model_json_schema but restricted to the subclass's data columns, in declaration order (see field_specs).

Returns:

Type Description
dict[str, Any]

A JSON Schema dict whose properties are the data columns.

reconcile ¶

reconcile(
    rows: list[dict[str, Any]],
) -> list[dict[str, Any]]

Reconcile rows against this schema.

Fields are coerced one by one through per-field TypeAdapters — the row-wise mirror of the DataFrame representation's column-wise casts. Extra keys are dropped (their union logged as a warning), missing fields get their default (or None, which pydantic accepts only for nullable fields), and scalar str fields are stringified up front since pydantic's lax mode never coerces to str.

This is more permissive than validate — it actively transforms data to match the schema rather than rejecting mismatches.

Parameters:

Name Type Description Default
rows list[dict[str, Any]]

List of row dicts.

 required

Returns:

Type Description
list[dict[str, Any]]

A new list of row dicts with columns aligned and types coerced.

Raises:

Type Description
SchemaError

If a value cannot be coerced (e.g. "abc" → int) or a required non-nullable field is missing.

Normalizer ¶

Normalizer(**data: Any)

Bases: Serializable

Type-native normalizer for list[dict] asset data.

Applies optional transformations to rows (column-name normalization, nested-dict flattening, missing-column fill). The shapes an asset may return besides rows (a generator, models, a lone dict) are unwrapped by the asset before normalization, so a normalizer only ever reshapes rows.

Normalizer is Serializable so instances round-trip through Spec with their concrete subclass intact — e.g. across the host → child-pod DAG-spec boundary.

Usage:

@asset(normalizer=Normalizer())
def my_asset(context):
    return [{"UserName": "alice", "Address": {"City": "NYC"}}]

Attributes:

Name Type Description
normalize_columns_names bool

Convert column names to snake_case.
flatten_max_level int | None

Maximum nesting depth to flatten. 0 disables flattening, None flattens without limit, a positive int flattens up to that many levels.
flatten_separator str

Separator for flattened key names.
fill_missing bool

Fill missing keys across rows with None so every row has the same columns.
replace_empty_dicts bool

Replace {} values with None.
replace_empty_strings bool

Replace "" values with None.
drop_na_columns bool

Drop columns where every value is None.
snake_case_digits bool

Treat digit groups as words when snake-casing column names (acosClicks14d → acos_clicks_14d instead of acos_clicks14d). Off by default because the right convention depends on the upstream API's naming semantics.
column_overrides dict[str, str]

Explicit raw-name → normalized-name mapping, applied before the snake_case conversion. For API quirk names no general rule can handle (eCPAddToCart → ecp_add_to_cart).

MaterializationStrategy ¶

Bases: str, Enum

How the conform step enforces an asset's schema.

Both strategies hand destinations data in the schema's canonical types; they differ in what counts as an error.

Attributes:

Name Type Description
RECONCILE

The default. Align columns to the schema (extras dropped with a warning, missing nullables filled) and coerce values. With no schema declared, infer one from the data for the destinations.
STRICT

Schema required. Extra columns, missing required columns and values the schema rejects fail the materialization; values that pass are still coerced to the declared types.
